Getting Started with the PSoC 5

Five short exercises that take you from a blank chip to wireless telemetry. Each one practices a technique the car will need.

TL;DR

Work the exercises in order on a spare dev board. Everything runs from the programming USB cable — no batteries. When something doesn't work, each exercise has a troubleshooting section built from real debugging sessions on this exact hardware.

Why this tutorial exists

A PSoC 5LP microcontroller controls the car. Before you can make it hold 4 ft/s up a hill or follow a taped line at speed, you need to be fluent in the PSoC workflow: drawing hardware in a schematic editor, assigning pins, and driving that hardware from C. Each exercise practices that workflow on a piece the car will use later:

The build–program–run loop, and the display you'll debug with all semester.

Streaming data off the board by radio, so you can tune a moving car from the bench.

Setup (once)

  1. Install PSoC Creator 4.4

    The installer is in the course files (psoccreator_4.4_Windows_x86-x64.exe). Accept the defaults; it bundles the C compiler and needs no license step. Windows only — the lab machines have it installed.

  2. Plug into the right USB jack

    The board has two identical mini-USB jacks. The programming jack is at the board corner next to the round DC barrel jack — it belongs to the onboard programmer. The other jack is the PSoC's own USB port: wrong, but harmless; just move the cable.

  3. Confirm Windows sees the programmer

    Open Device Manager (Win+X → Device Manager, or run devmgmt.msc). The board should enumerate as a Cypress DVKProg device. If it doesn't, you're probably in the wrong USB jack.

  4. Know the first-time programming dialog

    The first Debug → Program shows a Select Debug Target dialog: expand the DVKProg entry, select the chip (CY8C5868…), click Port Acquire / Connect, then OK. It remembers after that.

No batteries needed

The programming USB cable powers the whole board for every tutorial exercise. Batteries only matter once you move to the car.

Standing caution

Programming the bench-306 test car's PSoC permanently erases Radd's firmware — there is no way to read source code back off a chip. Do tutorial work on a spare dev board, or clear it with Radd first.

Aside Battery facts, for when you do move to the car

The car carries two separate packs, switched by the two toggle switches at its rear:

  • A 9.6 V pack (8 NiMH cells) feeds the electronics rail: terminal block → regulator board (two 7805s and a 7806) → PSoC, camera, and Hall sensor.
  • A 7.2 V pack (6 cells) feeds the drive motor through the MOSFET board.

If a pack is unlabeled, identify it by cell count or with a DMM: a charged 6-cell reads about 7.5–8.4 V, an 8-cell about 10–11 V. Never swap them — 9.6 V overdrives the motor.

How to use this site

  • Steps are the things you do; do them in order.
  • Going deeper boxes are optional expansions connecting what you just did to material from your circuits, signals, and computer architecture courses. Skip them under time pressure; read them before the design milestones.
  • On the car boxes (orange) point at the car subsystem each technique becomes.
  • Gotcha boxes (red) are mistakes that were made building this walkthrough, so you don't have to repeat them.
  • If the pixel styling is hard on your eyes, the Easy-read style button in the header switches the whole site to plain high-contrast typography. Your choice is remembered.
