Exercise 1

Hello World on the LCD

One schematic component and three lines of C. The edit–build–program loop here is the one you will repeat all semester.

On the car

The LCD is your fastest debugging tool all semester: printing a sensor reading or a PID term to the screen is often quicker than setting up telemetry. Getting fluent with it now pays off at every milestone.

Steps

  1. Create the project

    File → New → Project (the Start Page's "Create New Project" does the same). Choose a Design project, target device family PSoC 5LP, part CY8C5868AXI-LP035 (read the part number directly off the chip), and the Empty Schematic template. Name it and finish.

  2. Place the LCD component

    In the Component Catalog, open Display → Character LCD and drag it onto TopDesign.cysch. Double-click it and rename it to LCD.

  3. Assign the pins

    Open Design Wide Resources → Pins and set LCD:LCDPort = P2[6:0]. Port 2 is printed on the board silkscreen next to the LCD connector.

  4. Write the code

    Open main.c. All three lines go in the initialization section — after CyGlobalIntEnable;, before the for(;;) loop:

    LCD_Start();
LCD_Position(0u, 0u);
LCD_PrintString("Hello World");
    Code check — your whole main.c 
    #include "project.h"

int main(void)
{
    CyGlobalIntEnable; /* Enable global interrupts. */

    LCD_Start();
    LCD_Position(0u, 0u);
    LCD_PrintString("Hello World");

    for(;;)
    {
    }
}
  5. Build and program

    Build (Shift+F6) until you see "Build Succeeded", then Debug → Program. On "Successfully programmed" the board resets itself and runs your code.

Gotcha

Blank LCD after a successful program? Before you touch the code, turn the contrast trimpot next to the LCD. It is the most common false alarm in this exercise — see it on the board.

What just happened

Going deeper Why an infinite loop instead of returning from main?

Programs you've written for an OS do their work and return, and the OS takes back over. Here there is no OS and nowhere to return to, so every embedded program ends in an intentional infinite loop: for(;;).

The same structure organizes all your car firmware: code before the loop runs once (initialization), code inside the loop runs forever (continuous work). Later, interrupts will do the time-critical work and the loop can even sit empty.

Going deeper Where did LCD_Start() come from?

You never wrote it; the Build step generated it. When PSoC Creator builds your project it synthesizes the schematic into hardware configuration and emits a C API for every component, named after the component: name the block LCD and you get LCD_Start(); rename the block and the whole API renames.

This is also why #include "project.h" shows a red X before your first build: the file doesn't exist until Build generates it. Build once and the error disappears.

The generated functions write to memory-mapped registers: peripheral control presented as memory addresses, the same mechanism you saw (or will see) in computer architecture. The API saves you from looking up the addresses.

Going deeper The build output is worth reading

The build log ends with flash and RAM usage percentages. Flash holds your program (persistent, written by the programmer); RAM holds your variables (volatile, tiny — kilobytes, not gigabytes). On a desktop you almost never think about this; on a microcontroller running out of RAM is a real failure mode. Glance at these numbers as your car firmware grows.

Checkpoint

The LCD shows Hello World. You've been through the full loop: schematic → pin assignment → C code → build → program → running hardware. Every exercise from here on is that loop with more interesting hardware.
